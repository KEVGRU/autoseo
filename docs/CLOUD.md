# AutoSEO Cloud architecture (shared instance)

AutoSEO Cloud (`cloud/`, https://autoseo.codext.de) sells AutoSEO as a hosted service for $50/month. All
customers live in **one shared AutoSEO instance** (the open-source app from this repository) at
**https://app.autoseo.codext.de**. Every customer gets their **own workspace** in that instance; they are the
workspace *owner*, never an instance admin. The operator (Codext) is the only instance admin and configures AI
providers, DataForSEO, Google OAuth and limits once for everybody.

Self-hosting is unaffected: none of the behaviour below is active unless `AUTOSEO_CLOUD_API_SECRET` is set.

```
            Stripe ──webhooks──▶ cloud (autoseo.codext.de)  ──internal HTTP──▶  app (app.autoseo.codext.de)
 customer ─ signup / billing ──▶  marketing, accounts,        POST/PATCH/DELETE   shared AutoSEO instance,
                                  checkout, admin             /api/cloud/*        one workspace per customer
 customer ─────────── "Open AutoSEO" (signed SSO link) ──────────────────────────▶ /auth/sso
```

Both apps (plus one PostgreSQL each) run in the **same Coolify resource** (`cloud/docker-compose.yml`), so a single
push to `main` updates everything. The shared secrets are generated by Coolify (`SERVICE_PASSWORD_64_*`) and never
typed by hand.

## Environment

| Service | Variable | Value |
|---|---|---|
| app | `DOMAIN` | `app.autoseo.codext.de` |
| app | `AUTOSEO_OWNER_EMAIL` / `AUTOSEO_WORKSPACE_NAME` | operator account + operator workspace (first boot only) |
| app | `AUTOSEO_CLOUD_URL` | `https://autoseo.codext.de` (marks the instance as *managed*, shows billing links) |
| app | `AUTOSEO_CLOUD_API_SECRET` | `${SERVICE_PASSWORD_64_CLOUDAPI}` — enables the tenant API and multi-tenant hardening |
| app | `AUTOSEO_SSO_SECRET` | `${SERVICE_PASSWORD_64_CLOUDSSO}` |
| cloud | `CLOUD_APP_INTERNAL_URL` | `http://app:3000` (Docker network) |
| cloud | `CLOUD_APP_URL` | `https://app.autoseo.codext.de` |
| cloud | `CLOUD_API_SECRET` / `CLOUD_SSO_SECRET` | the same two Coolify-generated values |

## Tenant API (app side)

All endpoints live under `/api/cloud/`, require `Authorization: Bearer <AUTOSEO_CLOUD_API_SECRET>` (timing-safe
comparison) and return `404` when the variable is not set. JSON in, JSON out. `tenantId` is the cloud's instance id
(opaque string, ≤ 64 chars `[A-Za-z0-9_-]`).

| Method & path | Body | Result |
|---|---|---|
| `GET /api/cloud/health` | – | `{ ok: true, commit }` |
| `PUT /api/cloud/tenants/{tenantId}` | `{ ownerEmail, ownerName?, workspaceName, status?: "active"\|"suspended", suspendedReason?, limits?: { monthlyBudgetUsd?, maxProjects? } }` | Idempotent upsert. Creates the owner user (never instance admin) and the workspace on first call, links them (`owner` role), and on later calls updates name / status / limits. Returns `{ tenantId, workspaceId, ownerUserId, status }` |
| `GET /api/cloud/tenants/{tenantId}` | – | `{ tenantId, workspaceId, status, name, members, projects, spendThisMonthUsd, limits }` or `404` |
| `DELETE /api/cloud/tenants/{tenantId}` | – | Deletes the workspace with all its data and files, purges workspace-keyed rows (`usage_events`, `jobs`, `audit_logs`, `api_request_logs`), and erases users whose only membership was this workspace. Idempotent (`404` → treated as done by the cloud) |
| `PUT /api/cloud/config` | `{ mail: { smtpUrl, from } \| null }` | Platform default mail server (stored encrypted) used while Admin → Email is not configured |

## Multi-tenant rules in the app (only when `AUTOSEO_CLOUD_API_SECRET` is set)

- **Instance admin** is exactly `users.isInstanceAdmin`; roles can never grant `admin.access`.
- **SSO never signs in instance admins**: a compromised cloud must not be able to mint operator sessions. The operator
  signs in to the app with email; the cloud's "Open app" admin link is a plain link to `app.autoseo.codext.de/login`.
- **Suspended workspaces** are invisible to their members (pages, server actions, API v1, MCP, agents, share
  links, public endpoints) and all their scheduled work stops. Members see a "workspace paused" page linking to
  `AUTOSEO_CLOUD_URL/dashboard`. Instance admins still see them.
- **Per-workspace limits**: monthly spend budget (USD, provider cost) and max projects, set by the cloud per tenant.
  Budgets are enforced per workspace in addition to the instance budget.
- **No cross-tenant fallbacks**: the instance-wide Bing key is not used for tenant projects; the private-network
  allowlist is ignored (as for all managed instances); invite rate limits are keyed per workspace.
- Customers cannot see raw provider cost or the operator's markup; they see usage against their included budget.

## Lifecycle (cloud side)

| Event | Tenant |
|---|---|
| Checkout completed / admin grant | `PUT` (status `active`), owner gets the "workspace ready" email |
| Subscription `active` / `trialing` / `past_due` | `PUT` status `active` |
| Subscription `unpaid` / `canceled` / deleted | `PUT` status `suspended` (data kept 30 days) |
| Account deletion / admin delete | `DELETE` |

## Dedicated instances (optional)

The earlier model — one Coolify service per customer at `https://<slug>.autoseo.codext.de`, see
[`MANAGED_INSTANCES.md`](MANAGED_INSTANCES.md) — stays available as an admin-only option for customers who need
their own instance. New signups use the shared instance.
